# UPTRAND 홈페이지 관리자 매뉴얼

이 문서 하나면 홈페이지를 운영할 수 있습니다. **코드를 몰라도 됩니다.**

---

## 1. 홈페이지가 돌아가는 방식

```
구글 시트에서 내용 수정
        ↓
[사이트 업데이트] 실행
        ↓
GitHub 가 1~2분간 새 홈페이지를 만듦
        ↓
방문자에게 반영
```

**중요한 점 세 가지**

- **내 컴퓨터는 서버가 아닙니다.** 노트북을 꺼도 홈페이지는 계속 떠 있습니다. GitHub 가 대신 켜 두고 있습니다.
- **시트를 고치는 것만으로는 반영되지 않습니다.** 아래 2번의 갱신 절차를 거쳐야 합니다.
- **잘못 적으면 배포가 멈추고 이유를 알려줍니다.** 이상한 내용이 홈페이지에 올라가는 일은 없습니다.

---

## 2. 홈페이지 갱신하기

시트를 고친 뒤, 아래 셋 중 하나만 하면 됩니다.

| 방법 | 하는 법 | 반영 시간 |
| --- | --- | --- |
| **시트 메뉴** (가장 편함) | 시트 상단 **UPTRAND → 사이트 업데이트** | 1~2분 |
| **GitHub 버튼** | 저장소 → **Actions** 탭 → 왼쪽 `Deploy to GitHub Pages` → **Run workflow** | 1~2분 |
| **자동** | 아무것도 안 함 | 매일 오전 9시, 오후 9시 |

### 갱신이 잘 됐는지 확인

저장소의 **Actions** 탭을 열면 실행 목록이 보입니다.

- **초록 체크(✓)** — 성공. 홈페이지에 반영됐습니다.
- **빨간 엑스(✗)** — 실패. 항목을 클릭하고 `Build static site` 를 펼치면 아래처럼 이유가 한글로 나옵니다.

```
────────────────────────────────────────
시트를 읽지 못해 배포를 멈췄습니다.

시트 내용에 문제가 있습니다:
  · 게임 주소이름 "마음을담아"에 영문 소문자·숫자·하이픈 외의 글자가 있습니다.

시트를 고친 뒤 Actions 탭에서 다시 실행해 주세요.
────────────────────────────────────────
```

시트를 고치고 다시 실행하면 됩니다. **실패해도 기존 홈페이지는 그대로 살아 있습니다.**

## 3. 시트 탭 안내

시트에는 탭이 9개 있습니다. 자주 쓰는 것부터 정리했습니다.

### 자주 고치는 탭

#### `게임` — 새 게임을 출시했을 때

| 열 | 적는 법 |
| --- | --- |
| 주소이름 | 영문 소문자·숫자·하이픈만. 겹치면 안 됨 (예: `neon-drift`) |
| 제목 | 게임 이름 |
| 한 줄 소개 | 카드에 보이는 짧은 설명 |
| 상태 | `개발 중` 또는 `완료` |
| 태그 | 쉼표로 나열 (예: `Puzzle, Visual Novel`) |
| 썸네일 | `/images/파일이름.png` (5번 참고) |
| 플레이 영상 | 유튜브 **임베드** 주소 (6번 참고) |
| 스크린샷 | 한 줄에 하나씩 `설명 \| /images/파일.png` |
| 개발 기간 | 예: `2025.03 ~ 2025.10` |
| 참여 인원 | 예: `기획 2, 아트 3, 프로그래밍 2` |
| 개발 도구 | 쉼표로 나열 |
| 본문 | 한 문단에 한 줄 |
| 링크 | 한 줄에 하나씩 `이름 \| 주소 \| play` (또는 `download`) |
| 상세 페이지 | 따로 만든 소개 페이지가 있을 때만. 없으면 비워 두면 버튼이 안 나옵니다 |
| 성과 | 수상·전시 내역. **여러 건이면 한 줄에 하나씩** (칸 안에서 `Alt + Enter`) |

> 게임은 화면에 **4개까지만** 보이고 나머지는 `더보기` 를 눌러야 나옵니다. 순서는 시트의 위에서부터입니다.

#### `활동사진` — 행사 사진을 올릴 때

한 줄이 **앨범 하나**입니다. 클릭하면 좌우로 넘겨 보는 창이 뜹니다.

| 열 | 적는 법 |
| --- | --- |
| 주소이름 | 영문 소문자·숫자·하이픈만, 겹치면 안 됨 |
| 제목 / 요약 | 앨범 창 상단에 표시 |
| 분류 | `세미나`, `게임잼`, `스터디`, `컨퍼런스`, `외부행사` 등. **여기 적은 값이 그대로 필터 버튼이 됩니다** |
| 기간 | 예: `2025.09.20 ~ 2025.09.21` |
| 대표 사진 | 목록 격자에 보이는 사진 |
| 사진 | 한 줄에 하나씩 `설명 \| /images/파일.png` |

#### `타임라인` — 수상·행사 이력

| 열 | 적는 법 |
| --- | --- |
| 분류 | `공모전`, `전시회`, `기타`. **여기 적은 값이 필터 버튼이 됩니다** |
| 날짜 | 목록에 보이는 값 (예: `2025.10`) |
| 기간 | 창 안에 보이는 값 (예: `2025.11.13 ~ 2025.11.16`) |
| 주최 / 성과 한 줄 | 창 안의 요약 정보 |
| 자세히 링크 | 외부 기사 등. 없으면 비워 두면 버튼이 안 나옵니다 |
| 수상작 | 한 줄에 하나씩 `상 이름 \| 작품명 \| 게임주소이름` |
| 본문 / 사진 | 행사형 항목에 사용 |

> **수상작의 게임주소이름은 `게임` 탭에 실제로 있는 값이어야 합니다.** 오타가 나면 배포가 멈추고 알려줍니다.

#### `모집` — 모집 시즌마다

`모집 중` 을 `FALSE` 로 두면 지원 버튼이 비활성화되고 안내 문구가 대신 나옵니다. 모집을 시작할 때 `TRUE` 로 바꾸고, `기본정보` 탭의 `지원서 링크` 에 구글 폼 주소를 넣으세요.

### 가끔 고치는 탭

- **`기본정보`** — 동아리 이름, 히어로 제목, 이메일, 지원서 링크
  - 히어로 제목은 `새로운 [트렌드]를` 처럼 적습니다. **대괄호 안이 주황색**이 됩니다.
- **`소개`** — ABOUT US 의 글, 통계 숫자 2개, 소개 영상
- **`SNS`** — 푸터 아이콘. 아이콘 이름은 `instagram`, `github`, `youtube`, `discord`, `steam`, `itch` 중에서만
- **`활동내용`** — 프로젝트/게임잼/스터디 등 카드. `넓게` 에 `TRUE` 면 한 줄을 다 쓰는 큰 카드
- **`혜택`** — BENEFITS 4장. 아이콘은 `swords`, `graduation-cap`, `monitor-play`, `users` 중에서만

---

### 시트를 CSV 로 가져올 때 주의할 점

**붙여넣기(Ctrl+V)로 옮기면 안 됩니다.** 본문·스크린샷·링크처럼 **칸 안에 줄바꿈이 있는 데이터**가 깨지면서, 여러 줄이 한 칸에 뭉쳐 들어갑니다. 겉으로는 값이 다 있어 보이지만 머리글까지 뭉개져 배포가 실패합니다.

반드시 이렇게 하세요.

1. 해당 탭의 내용을 전체 선택해 지웁니다. (탭 자체는 남겨 둡니다)
2. **파일 → 가져오기 → 업로드** 에서 CSV 를 올립니다.
3. **가져오기 위치**를 **`현재 시트 바꾸기`** 로 선택합니다.
4. **구분 문자**를 **`쉼표`** 로 명시합니다. `자동 감지` 로 두면 깨질 수 있습니다.

## 4. 시트 작성 규칙

지키지 않으면 배포가 멈춥니다. 어렵지 않습니다.

1. **주소이름** 은 영문 소문자·숫자·하이픈만. 한글·공백·대문자 안 됩니다. 서로 겹쳐도 안 됩니다.
2. **머리글(첫 줄)을 지우거나 이름을 바꾸지 마세요.** 열 순서도 그대로 두세요.
3. **TRUE / FALSE** 는 대문자로. 체크박스를 넣어도 됩니다.
4. **한 칸에 여러 줄** 을 넣을 때는 칸 안에서 `Alt + Enter`.
5. **`설명 | 경로`** 형태는 세로줄(`|`) 로 구분합니다. 쉼표가 아닙니다.
6. 줄을 통째로 지우면 그 항목이 홈페이지에서 사라집니다. **되돌리려면 시트에서 `Ctrl+Z`** 하거나 시트 메뉴의 `파일 → 버전 기록` 을 쓰세요.

## 5. 이미지 넣기

이미지는 **구글 드라이브가 아니라 저장소에 올립니다.** 드라이브는 안정적인 이미지 주소를 주지 않아 홈페이지에서 깨집니다.

1. GitHub 저장소에서 `public` → `images` 폴더로 들어갑니다.
2. **Add file → Upload files** 를 누르고 이미지를 끌어다 놓습니다.
3. 아래 **Commit changes** 를 누릅니다.
4. 시트의 이미지 칸에 `/images/파일이름.png` 라고 적습니다.

> 파일 이름은 **영문·숫자·하이픈**으로 지어 주세요. 한글 파일명은 주소에서 깨질 수 있습니다.
>
> 이미지를 비워 두면 색이 있는 임시 그림이 대신 표시됩니다. 준비된 것부터 하나씩 채워도 됩니다.

---

## 6. 유튜브 영상 넣기

주소창의 주소를 그대로 붙이면 안 됩니다. **임베드 주소**로 바꿔야 합니다.

| | 주소 |
| --- | --- |
| ❌ 그대로 | `https://www.youtube.com/watch?v=**AbCdEf12345**` |
| ✅ 이렇게 | `https://www.youtube.com/embed/**AbCdEf12345**` |

`watch?v=` 를 `embed/` 로 바꾸면 됩니다. 유튜브에서 **공유 → 퍼가기** 를 누르면 나오는 주소를 써도 됩니다.

## 7. 처음 한 번만 하는 설정

이미 되어 있다면 넘어가세요. 다음 기수에 인수인계할 때 참고용입니다.

### 7-1. GitHub Pages 켜기

저장소 **Settings → Pages → Source** 를 `Deploy from a branch` 가 아니라 **`GitHub Actions`** 로 바꿉니다.

주소는 `https://<계정>.github.io/<저장소이름>/` 이 됩니다.

### 7-2. 시트 연결하기

1. 저장소에서 `sheet-template` 폴더의 CSV 9개를 내려받습니다.
2. 구글 시트를 새로 만들고, **CSV 파일 이름과 똑같은 이름의 탭**을 만들어 각각 가져옵니다.
   (파일 → 가져오기 → 업로드 → **현재 시트에 삽입**)
3. 시트 **공유** 를 **"링크가 있는 모든 사용자 · 뷰어"** 로 바꿉니다. 이걸 안 하면 읽지 못합니다.
4. 시트 주소에서 ID 를 복사합니다.
   `https://docs.google.com/spreadsheets/d/`**`이 부분이 ID`**`/edit`
5. 저장소 **Settings → Secrets and variables → Actions → Variables** 탭 → **New repository variable**
   - Name: `SHEET_ID`
   - Value: 4번에서 복사한 값

### 7-3. 시트에 업데이트 버튼 달기 (선택)

시트에서 **확장 프로그램 → Apps Script** 를 열고 아래를 붙여 넣습니다. `OWNER`, `REPO`, `TOKEN` 을 채우고 저장한 뒤 시트를 새로고침하면 상단에 `UPTRAND` 메뉴가 생깁니다.

토큰은 GitHub → Settings → Developer settings → **Fine-grained personal access token** 에서 해당 저장소의 `Contents: Read and write` 권한으로 만듭니다.

```javascript
const OWNER = '계정이름';      // 예: uptrand-admin
const REPO  = '저장소이름';    // 예: Homepage
const TOKEN = 'github_pat_...';

function onOpen() {
  SpreadsheetApp.getUi().createMenu('UPTRAND')
    .addItem('사이트 업데이트', 'updateSite').addToUi();
}

function updateSite() {
  const res = UrlFetchApp.fetch(
    `https://api.github.com/repos/${OWNER}/${REPO}/dispatches`,
    {
      method: 'post',
      contentType: 'application/json',
      headers: {
        Authorization: 'Bearer ' + TOKEN.trim(),
        Accept: 'application/vnd.github+json',
      },
      payload: JSON.stringify({ event_type: 'update-content' }),
      muteHttpExceptions: true,
    }
  );

  const code = res.getResponseCode();
  if (code === 204) {
    SpreadsheetApp.getUi().alert('업데이트를 시작했습니다.\n1~2분 뒤 홈페이지를 확인하세요.');
    return;
  }

  // 숫자만 보여주면 원인을 알 수 없으므로, 무엇을 고쳐야 하는지 함께 띄운다.
  const hint = {
    401: '토큰이 잘못됐습니다. TOKEN 값을 다시 확인하세요.',
    403: '토큰 권한이 부족합니다. Contents 를 Read and write 로 주세요.',
    404: '저장소를 찾을 수 없습니다. OWNER 와 REPO 철자를 확인하세요.',
  }[code] || '알 수 없는 오류입니다.';

  SpreadsheetApp.getUi().alert(
    '실패 (' + code + ')\n\n' + hint + '\n\nGitHub 응답:\n' + res.getContentText()
  );
}
```

> **토큰은 만료됩니다.** 만들 때 만료일을 적어 두고, 인수인계 문서에 남겨 주세요. 만료되면 버튼만 동작하지 않고, Actions 탭의 수동 실행은 계속 됩니다.

## 8. 문제가 생겼을 때

| 증상 | 원인과 해결 |
| --- | --- |
| 시트를 고쳤는데 홈페이지가 그대로 | 갱신을 실행하지 않았습니다. 2번 참고 |
| Actions 가 빨간 엑스 | 로그에 한글로 이유가 나옵니다. 시트를 고치고 다시 실행 |
| `시트를 읽을 권한이 없습니다` | 시트 공유가 비공개로 바뀌었습니다. 7-2의 3번 참고 |
| `머리글이 다릅니다` | 첫 줄의 열 이름을 고쳤거나 열을 지웠습니다. 되돌리세요 |
| 이미지가 안 보임 | 파일이 `public/images` 에 없거나 시트의 경로에 오타. `/images/` 로 시작하는지 확인 |
| 영상이 안 나옴 | `watch?v=` 를 `embed/` 로 바꾸지 않았습니다. 6번 참고 |
| 홈페이지 전체가 안 열림 | Settings → Pages 의 Source 가 `GitHub Actions` 인지 확인 |

### 시트 버튼이 실패할 때 (숫자별)

버튼이 실패하면 창에 숫자가 뜹니다. 숫자마다 원인이 다릅니다.

| 숫자 | 뜻 | 해결 |
| --- | --- | --- |
| **401** | 토큰이 잘못됐습니다 | 토큰 문자열을 다시 확인하세요. `github_pat_` 로 시작하는 값 전체를 따옴표 안에 넣었는지, 앞뒤에 공백이나 줄바꿈이 섞이지 않았는지 봅니다. 토큰을 새로 만들었다면 Apps Script 의 `TOKEN` 도 바꿔야 합니다 |
| **403** | 토큰은 맞지만 권한이 없습니다 | 토큰의 **Repository access** 에 이 저장소가 포함됐는지, **Permissions → Contents** 가 `Read and write` 인지 확인 |
| **404** | 저장소를 못 찾습니다 | `OWNER` 와 `REPO` 철자를 확인하세요. 대소문자도 정확해야 합니다 |
| **204** | 성공 | 정상입니다 |

> 토큰을 만들 때 **Contents 를 `Read and write`** 로 주지 않으면 동작하지 않습니다. 읽기 전용으로는 배포를 시작시킬 수 없습니다.
>
> 버튼이 안 되더라도 **Actions 탭의 Run workflow 는 계속 쓸 수 있습니다.** 급하면 그쪽으로 갱신하세요.

## 부록. 개발자용

코드를 고쳐야 할 때만 필요합니다.

```bash
npm install
```

```bash
npm run dev
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:3000) |
| `npm run build` | 정적 사이트를 `out/` 에 생성 |
| `npm run sheet:check` | **시트가 배포 가능한 상태인지 점검** (아무것도 고치지 않음) |
| `npm run content` | 구글 시트를 읽어 `content.json` 갱신 (`SHEET_ID` 필요) |
| `npm run sheet:template` | 현재 내용으로 시트 양식 CSV 재생성 |

### 시트 점검하기

시트를 크게 손본 뒤, 사이트 업데이트를 누르기 전에 미리 확인할 수 있습니다.

```bash
SHEET_ID="시트 주소" npm run sheet:check
```

```
  탭        줄 수   상태
  ──────────────────────────
  기본정보      10   정상
  게임          1   문제 2건
  소개          6   문제 1건
  ...

[게임]
  · 머리글에 없는 열: 주소이름, 제목, 한 줄 소개, ...
  · 머리글 칸에 값이 함께 들어가 있습니다. 붙여넣기 대신
    파일 → 가져오기 → 현재 시트 바꾸기 로 다시 넣어 주세요.
```

배포와 **같은 판정**을 쓰므로, 여기서 모두 정상이면 배포도 통과합니다. 문제가 있는 탭은 **한 번에 모두** 알려주므로 하나씩 고치고 다시 돌릴 필요가 없습니다.

**콘텐츠가 흐르는 경로**

```
구글 시트
   ↓  scripts/fetch-sheet.mjs   (빌드 직전, SHEET_ID 있을 때만)
src/data/content.json           ← 사이트의 유일한 콘텐츠 원본
   ↓  src/data/content.ts       (타입을 입혀 내보내는 얇은 래퍼)
페이지 컴포넌트
```

탭이나 열을 바꾸려면 **`scripts/sheet-schema.mjs` 한 곳만** 고칩니다. 양식을 만드는 쪽과 읽는 쪽이 같은 정의를 공유하므로 서로 어긋나지 않습니다. `npm run sheet:template` 은 내보낸 뒤 다시 읽어 원본과 같은지 스스로 검사하고, 다르면 실패합니다.

**주의할 점 두 가지**

- `public/` 안의 이미지를 코드에서 쓸 때는 반드시 `asset()` 을 거쳐야 합니다 (`src/lib/asset.ts`). GitHub Pages 는 주소에 저장소 이름이 들어가는데, 이미지 최적화를 끈 상태에서는 그 경로가 자동으로 붙지 않아 404 가 납니다.
- `scripts/flatten-prefetch.mjs` 는 Next.js 16.3.0 정적 내보내기 버그를 우회합니다. 없으면 링크 프리페치가 전부 404 가 나면서 페이지 이동마다 전체 새로고침이 일어납니다. Next 업그레이드로 해결되면 이 스크립트와 `package.json` 의 `postbuild` 항목을 지워도 됩니다.
